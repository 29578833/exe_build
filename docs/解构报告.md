## 五、"影响用户使用"根因分析

1. **内核太老**：客户端内核是 2016 年的 Chrome 50，网站已迭代到 v5.10.6。
   网站每次发布新版本，都可能引入旧内核不支持的特性（async/await 需 Chrome 55+、
   CSS Grid 需 Chrome 57+、可选链需 Chrome 80+），一旦引入就是白屏/功能异常。
2. **安全隐患**：Chrome 50 有大量已公开的严重漏洞（CVE），无任何修复通道。
3. **依赖风险**：网站外链的第三方 JS（易盾、高德、GrowingIO）新版均不再兼容 Chrome 50。
4. **无自动更新**：壳本身没有升级通道，用户装了什么版本永远是什么版本。

## 六、优化方案（在现有基础上升级）

### 方案A：壳工程重建（保留 NW.js 架构，推荐）
1. 用已恢复的 package.json + node-main.js 重建工程（目录已备好）
2. 升级 NW.js 0.19 → 最新 LTS（0.9x，Chromium 130+），窗口/API 兼容，改动极小
3. 加原生能力：托盘图标、自动更新、本地缓存、下载管理、全局快捷键
4. Inno Setup 重新打包（附打包脚本）

### 方案B：迁移 Electron（长期推荐）
1. 架构等价迁移（main 字段加载远程 URL），生态更活跃
2. 内置自动更新（electron-updater）、崩溃上报（sentry）
3. 64位 + 代码签名 + 安全加固

### 方案C：网页端优先（不动壳）
1. 若主要矛盾是"用户打不开/白屏"，先做兼容性兜底：
   - 服务端检测 UA 识别旧客户端，降级加载兼容 JS（babel-polyfill）
   - 或页面直接提示下载新客户端
2. 治标，不解决内核老化问题
