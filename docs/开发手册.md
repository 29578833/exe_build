## 3. 解构方法论（拿到任意安装包如何还原）

### 3.1 先验指纹，判定是不是原版
```bash
md5sum <拿到的安装包>
# 期望 59fcdb7e49e393b10e0b428d98174bfb = 官方原包（2018）
# 官方渠道: qixiubaodiannaoban_1.0.0.0_*.exe / QiXiuBaoInst*.exe 都是同一文件
```

### 3.2 鉴定技术栈（app-recon 流程）
- 安装包 = **NSIS**（不是 Inno！）：PE 资源 129-135 + `NullsoftInst` 标记 + `startInstall_*.png` 宣传图。
  `innoextract --info` 会报 "Not a supported Inno Setup installer!"。
- RAR 数据嵌在 PE 资源 **RES/132**（41.7MB）。
- 壳应用判定：解出后只有运行时 + package.json + 图标，无业务代码 → 网页壳。

### 3.3 提取内嵌 RAR（三个备选链，按顺序试）
1. **定位真 RAR**：`Rar!\x1a\x07\x00` 签名可能出现多个（有伪造损坏头干扰），**取最后一个签名偏移**截取。
   汽修宝实例：假头@1389913，真 RAR@1705396（0x1a05b4）。
2. **bsdtar（libarchive）**：`bsdtar -xf x.rar -C out/ "app/*"` 按模式提取（整包解会 CRC error，按模式提取够用）。
   无 root 装包：`apt-get download libarchive-tools && dpkg -x <deb> dir/`，直接执行 `dir/usr/bin/bsdtar`。
3. **7z**：能 list 目录，但 RAR3 m3:22 压缩解出 0 字节（Unsupported Method）→ 只用来确认文件清单。
4. **unrar-free**：解 ASCII 文件名可以，遇中文文件名直接停 → 弃用。
5. **WinRAR 官方 UnRAR.exe**：最稳，但需 Windows + interop。

### 3.4 原版基准文件（解构后逐一对齐，改壳时以它为准）
- 原版 package.json = 2183 字节，version 1.0.0，build 1489637051，**无 node-main 字段、无 inject_js_start**。
- 原版 app/node-main.js = 51 字节：`process.env.CL_Argv = JSON.stringify(process.argv);`
- 4 个图标 MD5：1024.png=`46daa69f3075fdc575d294b401235867` logo.ico=`8c7ba48019bca4344ad5d13a9aefb443`
  logo.png=`530ec71d5422ece6f66eff86b56b3caa` blank.png=`8a1c30381e6343269d3a6a347ad6c764`
- 原版文件清单（82 个文件/125MB 解压后）：见 installer/unins000.dat + extracted/ 目录。

### 4.4 RAR 打包（⚠️ 头号坑：压缩级别必须与原版一致）
```
Rar.exe a -ma3 -m3 -ep1 -x*.pak.info newpack.rar <小文件...>
Rar.exe a -ma3 -m3 -ep1 -x*.pak.info newpack.rar *.exe
Rar.exe a -r -ma3 -m3 -ep1 -x*.pak.info newpack.rar app
Rar.exe a -r -ma3 -m3 -ep1 -x*.pak.info newpack.rar locales
Rar.exe a -r -ma3 -m3 -ep1 -x*.pak.info newpack.rar swiftshader
Rar.exe a -ma3 -m3 -ep1 newpack.rar nw.dll        # ★ 大文件排最后
```
**为什么必须 m3:22**：NSIS 内置旧解压器遇 m5 压缩的大文件（nw.dll）会静默丢尾部文件，
症状 = 装完缺主程序 exe。**大文件排 RAR 末尾、关键文件（package.json/resources.pak/主exe）排头部**。
排除 `*.pak.info`。

改 3 个常量：`SRC`（原版安装包）、`NEW_RAR`（§4.4 产物）、`OUT`（输出路径），然后：
```bash

# 输出: shift=+45MB, RES/132 Size 41711808 -> 90714528 之类，末尾 ✓ 已保存
```

## 6. 核心脚本

### 6.1 patch_installer.py（PE 资源补丁，NSIS 壳换 RAR）

原理：读原版 exe → 定位 .rsrc 段 → 把 RES/132 的 RAR 数据整体替换为新 RAR →
修正节表（.rsrc/.reloc 大小/偏移、SizeOfImage）→ 重写 RAR 之后所有资源条目的 RVA → 写盘。
关键常量（在脚本顶部，改这 3 个即可）：
```python
SRC     = "/home/kk/qxb-inst-analysis/inst.exe"        # ← 原版安装包
NEW_RAR = "/home/kk/qxb-inst-analysis/newpack.rar"     # ← 新 RAR
OUT     = "/home/kk/qxb-inst-analysis/QiXiuBaoInst_v2_win7.exe"  # ← 输出
OLD_RAR_OFF = 0x1a05b4     # 真 RAR 文件偏移（原包特征，换原包才要改）
OLD_RAR_SIZE = 41711808    # 原 RAR 字节数（原包特征）
OLD_RAR_RVA  = 0x1a57b4
```
脚本会自动断言 `orig[OLD_RAR_OFF:OLD_RAR_OFF+4] == b"Rar!"`，RAR 起点不对会报错，不会瞎写。
完整代码见 v2_win7/patch_installer.py（93 行，标准库 struct，零依赖）。

### 6.2 inject.js（刷新按钮修复，注入渲染进程）

**症状**：新内核下点网页上的"刷新"，窗口最小化/消失（0.72）或直接退出（0.90）。
**根因**：网页端 refresh() = 重启式刷新——`spawn(process.execPath) + win.hide() + win.close() + location.reload(true)`。
Chromium 108+ 的 ProcessSingleton 让同 profile 第二实例启动即退出 → 新进程起不来，
旧窗口已 hide+close → 应用没了。

**修复策略**（三件事）：
1. 劫持 `child_process.spawn`：自我重启（cmd==execPath 且无参数）只写标记，**不真启动**，返回带 `.unref()` 的哑对象。
2. 拦 `win.on('close')`：标记存在时 `preventDefault()`，阻止窗口被关。
3. `reload` 后 `win.show()` 恢复窗口（0.72 页面先 hide 了，不 show 刷新完看不见）。
4. 标记用 localStorage（跨 reload 存活），600ms 后清除。

**注意**：
- 注入用 `inject_js_start`（渲染进程），不能放 node-main（主进程 require('nw.gui') 在 0.90+ 不可用）。
- 哑对象必须带 `.unref()`（页面链式调用会访问）。
- 完整代码见 v2_win7/inject.js（53 行）。

### 6.3 网页端刷新锚点（PC_Chat.js，排查用）
```js
if(window.nw){ removeTray(); spawn(process.execPath, [], {detached:true}).unref(); win.hide(); win.close(); location.reload(true) }
```

## 7. 关键决策点与不可踩的坑

| # | 坑 | 说明 |
|---|----|------|
| 1 | **Win7 顶点 = 0.72.0** | 0.73+ 在 Win7 启动即崩（SetProcessMitigationPolicy 缺失）；要 Win7 就用 0.72，可弃 Win7 才考虑 0.90+ |
| 2 | **安装器必须保原版 NSIS 壳** | 用 Inno 重打包 = 安装向导变样，用户打回"跟之前不一样"。只换内嵌 RAR |
| 3 | **RAR 压缩级别必须 m3:22** | m5 会让 NSIS 旧解压器解 nw.dll 后静默丢尾部文件（装完缺 exe） |
| 4 | **大文件排 RAR 末尾** | 同坑 3 的配套措施；关键小文件排头部 |
| 5 | **主程序名保持 汽修宝电脑版.exe** | 快捷方式/进程/卸载器依赖，不能叫 nw.exe |
| 6 | **0.114 不能用于本壳** | node-main 里 nw.Window.get() 破坏远程页面 API（扫码登录失效）+ nw.gui 移除 + associated app window 限制。0.90 时代已实测否决，别走回头路 |
| 7 | **0.90 vs 0.72 刷新症状不同** | 0.90=直接退出；0.72=最小化/窗口消失。修复 inject.js 通吃（0.72 需多一步 win.show()） |
| 8 | **node-main 别碰窗口 API** | 0.90/0.114 下 node-main 顶层 nw.Window.get() 会破坏远程页面 |
| 9 | **不要"延迟 spawn 等锁释放"** | 渲染进程 close 后存活窗口 2-3s < 旧进程释放 profile 锁时间，2s/3s/4s 全灭 |
| 10 | **安装包无数字签名** | 原版就无签名（PE DataDirectory 无 Certificate Table），v2 保持 |
| 11 | **XP/Vista 必弃** | 原版 Chromium 50 最后支持 XP；新内核全不支持，无法兼顾 |
| 12 | **网页 UA 校验** | 服务器弹"版本过低"遮罩按 UA 判断（Chrome<50 弹）；新 UA Chrome/108 直接过，无需处理 |

## 10. 其它电脑导入步骤（新手也能上手）

1. 拷走最小集：`v2_win7/`（含脚本/README/安装包）+ `app/` + `package.json` + `installer/unins000.dat`
2. 装工具：python3、bsdtar、7z；Windows 侧装 WinRAR（打 RAR 用）
3. 拿原版安装包（官方下载或本地备份），`md5sum` 核对 `59fcdb7e...`
4. 若只是**再打一次 v2**：改 patch_installer.py 三个常量 → 跑 → 验证（§4.6）
5. 若要**迭代 v3**（换内核）：下载目标版 NW.js → 组装 build/（§4.3）→ RAR 打包（§4.4，m3:22！）
   → 补丁（§4.5）→ 验证（§4.6）。**先看 §7 坑表**，尤其 0.73+ 弃 Win7、0.114 不可用
6. 交付前先 `curl`/GUI 实测，验收标准：安装过程跟官方一致 + 启动正常 + 刷新正常 + 登录态保留
